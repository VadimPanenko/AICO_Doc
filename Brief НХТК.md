# Бриф (ООО «НХТК»)
## ИИ-агент для обработки входящей почты — автоматический реестр вагонов

---

# 1. Понимание задачи

На основании предоставленного опросника и примеров данных мы понимаем задачу следующим образом.

## 1.1 Что нужно создать

**ИИ-агент для обработки входящей почты**, который:

- Автоматически читает входящие письма с выделенного почтового ящика
- Извлекает номера вагонов из письма — текст, тема письма, фото, PDF
- Формирует ежедневный реестр: номер вагона, источник письма, дата, текст запроса
- Предъявляет результат оформителю для проверки и подтверждения
- Уведомляет оформителей по email о новых обработанных письмах
- Пересылает необработанные письма на отдельный адрес для ручной обработки
- Ведёт историю всех обработанных писем

## 1.2 Цели системы

| Цель | Описание |
|------|----------|
| Снижение ручного труда | Устранить ручной перенос данных из ~500 писем в день |
| Ускорение обработки | Сократить время обработки одного письма с 1:15 мин до пары секунд |
| Минимизация ошибок | Исключить пропуски и опечатки при ручном вводе |
| Масштабируемость | Обрабатывать пиковые нагрузки без увеличения штата |

## 1.3 Бизнес-процессы

Система затрагивает:
- Обработку входящих запросов на оформление вагонов от внешних партнёров, подрядчиков и коллег
- Ведение реестра вагонов оформителями
- Координацию между отправителями запросов и отделом оформления

## 1.4 Ожидаемые бизнес-метрики

- Доля писем, обработанных агентом корректно без участия человека: **90%**
- Сокращение ручных операций оформителя: с ~10 часов до ~1 часа в день
- Скорость формирования реестра: ежедневно, автоматически

# 2. Текущая ситуация

ООО «НХТК» — нефтехимическая транспортная компания, управляющая парком железнодорожных вагонов-цистерн. Оформители компании ежедневно получают запросы от партнёров, подрядчиков (СГ-транс, НОВАТЭК-АЗК и др.) и коллег с просьбами обработать вагоны — зарегистрировать, восстановить документ, подготовить перевозочные документы и т.п.

**Масштаб проблемы:**
- ~500 писем в день / ~3 500 в неделю на почтовый ящик оформления
- Среднее время ручной обработки одного письма: **1 мин 15 сек**
- Итого: **~10,4 часа ручной работы в день** только на перенос данных из писем

**Типы входящих писем (по реальным примерам):**

| Тип письма | Пример темы | Где номер вагона |
|---|---|---|
| Запрос восстановления | «76816800 ПРОСРОК» | В теме письма |
| Нет документов | «Нет документов Волжский ПРИВЖД» | В теле: «50512953 Волжский 57763971» |
| Отсутствие заготовки | «ООО Донсервисгаз» | В теле + JPG-вложение |
| Выход из ремонта | «выход из ремонта» | Структурированная таблица в теле (несколько вагонов) |

**Ключевые проблемы:**
- Высокая нагрузка на оформителей из-за полностью ручного процесса
- Разнородный формат писем — у каждого отправителя своя структура
- В одном письме может быть до **80 номеров вагонов** одновременно
- Ошибки и пропуски при ручном вводе
- Нет истории обработки: непонятно, какие письма были обработаны, а какие нет

# 3. Предлагаемое решение (PoV)

## 3.1 Скоуп PoV

> **Ключевой принцип:** В рамках данного этапа мы создаём агента, который **извлекает номера вагонов и формирует структурированный реестр для оформителя**. Интеграция с ЭТРАН, проверка принадлежности и оформления вагонов — задачи следующих возможных этапов.

### Что ВХОДИТ в PoV

- Чтение входящих писем с выделенного почтового ящика
- Извлечение номеров вагонов из: текста письма, темы письма, JPG-вложений (OCR), PDF-вложений
- Формирование ежедневного реестра: **Вагон | Источник email | Дата письма | Текст запроса**
- Веб-интерфейс для оформителя: просмотр результата и подтверждение
- Email-уведомление оформителям о новых обработанных письмах
- Перенаправление необработанных писем на отдельный адрес
- История обработки (логирование всех писем)

### Что НЕ ВХОДИТ в PoV

- Интеграция с системой ЭТРАН
- Проверка принадлежности вагона оператору
- Проверка статуса оформления (есть ли заготовка ГУ-12)
- Заполнение полных данных реестра: Группа, Станция назначения, Груз, Дорога
- Интеграция с корпоративными системами учёта

# 5. Бизнес-обоснование

> Данный раздел позволяет оценить целесообразность масштабирования после PoV.

**Текущие трудозатраты (расчёт на основе данных клиента):**

| Параметр | Значение |
|---|---|
| Писем в день | ~500 |
| Время на одно письмо | 1 мин 15 сек |
| Ручной труд в день | **~10,4 часа** |
| Ручной труд в месяц | **~220 часов** |

**Эффект при 90% автоматизации:**

| Параметр | Значение |
|---|---|
| Писем, обработанных агентом | ~450 из 500 в день |
| Остаток на ручную обработку | ~50 писем (~1 час в день) |
| Освобождённое время | **~9,4 часа в день / ~200 часов в месяц** |
| Срок окупаемости пилота (1 млн ₽) | **~2–3 месяца** при средней стоимости труда оформителя |

# 6. Технические требования

| Параметр | Значение |
|---|---|
| Почтовый ящик | Отдельный ящик, на который пересылаются письма с запросами |
| Подключение к почте | IMAP или Exchange API (платформа уточняется) |
| Развёртывание | На согласование — облако или on-premise |
| Внешние LLM | Допускаются на этапе PoV (без строгих требований ИБ) |
| Данные для тестирования | 5 дней истории писем |
| Количество тестировщиков | 2–3 оформителя |

---

# 7. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Малый объём тестовых данных (5 дней) | Высокая | Среднее | Использовать все доступные примеры; при необходимости — запросить дополнительные |
| Разнородный формат писем у разных отправителей | Высокая | Среднее | LLM устойчив к нестандартным форматам; чем больше примеров — тем лучше |
| Сложные PDF-вложения (сканы, нечёткие фото) | Средняя | Среднее | OCR + LLM пост-обработка; edge cases — в ручную обработку |
| До 80 вагонов в одном письме | Средняя | Среднее | Пакетная обработка; стресс-тест на реальных данных |
| Письма не связанные с вагонами в потоке | Высокая | Низкое | Классификатор отфильтровывает, пересылает на ручной ящик |
| Платформа почты не известна → нет API | Средняя | Высокое | Уточнить до старта; IMAP работает с большинством платформ |

# 10. Перспектива масштабирования (за рамками PoV)

При успешном пилоте возможны следующие направления:

- **Интеграция с ЭТРАН** — автоматическая проверка принадлежности вагона и статуса заготовки
- **Полное заполнение реестра** — автоматическое определение Группы, Станции, Груза, Дороги
- **Автоматическое создание черновика** в ЭТРАН без участия оформителя
- **Расширение типов входящих документов** — обработка Excel, Word, структурированных таблиц
- **Аналитика** — статистика по источникам, типам запросов, нагрузке
