# Бриф (ООО Алюмпарк)
## ИИ-ассистент для менеджеров по продажам

---

# 1. Понимание задачи

На основании предоставленного описания мы понимаем вашу задачу следующим образом:

## 1.1 Что нужно создать

**Чат-бот (ИИ-ассистент)** для менеджеров по продажам, который:

- Работает как **единое окно** для получения информации на естественном языке
- **Ликвидирует «тихие» простои** — время, которое менеджер тратит на сбор информации по звонкам и письмам
- Агрегирует данные из различных источников и формирует готовые ответы

## 1.2 Цели системы

| Цель | Описание |
|------|----------|
| Ускорение коммуникации | Мгновенные ответы на запросы о статусах, сроках, проблемах |
| Снижение рутины | Менеджер не тратит время на обзвон отделов |
| Проактивность | Выявление рисков и предложение решений |
| Единый интерфейс | Все данные доступны в одном месте через чат |

## 1.3 Бизнес-процессы

Система влияет на:
- Информирование клиентов о статусе заказов
- Координацию между отделами (продажи, производство, склад, закупки)
- Принятие оперативных решений при возникновении проблем

## 1.4 Ожидаемые бизнес-метрики

- Сокращение времени на сбор информации для клиента
- Ускорение реакции на проблемы (задержки, дефицит)
- Повышение удовлетворённости клиентов

---

# 2. Текущая ситуация (как мы её понимаем)

Сейчас менеджер по продажам для получения информации о заказе:

- Звонит в производство
- Пишет на склад
- Запрашивает данные в CRM / 1С
- Собирает ответы и формулирует информацию для клиента

**Ключевые проблемы:**
- Много времени уходит на коммуникацию внутри компании
- Информация разрознена по системам и людям
- Клиент ждёт, пока менеджер соберёт данные
- Риски и проблемы выявляются поздно

**Участники процесса:** менеджеры по продажам

---

# 3. Предлагаемое решение (PoC)

## 3.1 Ограничение PoC

> **Важно:** Для PoC не берём реальные интеграции с 1С, MES, CRM. Работаем на демо-данных или статических выгрузках.

## 3.2 Компоненты системы PoC

| # | Компонент | Назначение |
|---|-----------|------------|
| 1 | **Чат-интерфейс** | Telegram / веб-чат для общения с ботом |
| 2 | **LLM-модуль** | Обработка запросов на естественном языке |
| 3 | **База знаний** | Демо-данные: заказы, статусы, типовые проблемы |
| 4 | **Логика сценариев** | Формирование ответов, выявление рисков |

## 3.3 Что демонстрирует PoC

- Как будет выглядеть диалог с ботом
- Как бот формирует ответ из нескольких источников
- Как бот предлагает решения при проблемах
- UX взаимодействия для менеджера

## 3.4 Что НЕ входит в PoC

- Реальные интеграции с 1С, MES, CRM
- Работа с реальными данными в реальном времени
- Автоматизация действий (заказ закупок и т.д.)

## 4.3 Этапы реализации PoC

```
ЭТАП 1: ПОДГОТОВКА
├── Сбор требований и уточнение сценариев
├── Получение примеров данных / структуры данных
├── Выбор интерфейса (Telegram / веб)
└── Настройка окружения

ЭТАП 2: БАЗА ЗНАНИЙ
├── Создание структуры демо-данных
├── Наполнение тестовыми заказами, клиентами, статусами
└── Описание типовых проблем и решений

ЭТАП 3: AI-МОДУЛЬ
├── Настройка LLM
├── Логика извлечения сущностей из запроса
├── Логика поиска по базе знаний
├── Логика формирования ответа с рекомендациями
└── Тестирование диалогов

ЭТАП 4: ЧАТ-ИНТЕРФЕЙС
├── Разработка бота (Telegram / веб)
├── Интеграция с AI-модулем
└── UX: кнопки, быстрые действия

ЭТАП 5: ТЕСТИРОВАНИЕ И ДЕМО
├── Проверка сценариев
├── Сбор обратной связи
└── Демонстрация
```
