# Коммерческое предложение
## AI-платформа предиктивной аналитики промышленного оборудования

---

# 1. Понимание задачи

На основании предоставленного описания мы понимаем вашу задачу следующим образом:

## 1.1 Что нужно создать

**AI-платформа предиктивной аналитики** технического состояния промышленного оборудования для нефтеперерабатывающих и нефтехимических предприятий, которая:

- Агрегирует и хранит разнородные технические, сервисные и закупочные данные
- Анализирует их с помощью LLM (RAG)
- Формирует прогнозы, риски и рекомендации по обслуживанию и закупке ЗИП

## 1.2 Цели системы

| Цель | Описание |
|------|----------|
| AI-память предприятия | Создание постоянно обучающейся базы знаний |
| Анализ состояния | Оценка фактического и вероятного состояния оборудования |
| Выявление рисков | Обнаружение скрытых технических рисков |
| Прогнозирование | Предсказание отказов и потребностей в сервисе и ЗИП |
| Коммерческая поддержка | Усиление экспертной позиции при взаимодействии с заказчиками |

## 1.3 Бизнес-процессы

Система влияет на:
- Техническое обслуживание оборудования
- Планирование закупок ЗИП
- Аналитическую поддержку коммерческих решений
- Подготовку предложений для заказчиков

## 1.4 Ожидаемые бизнес-метрики

- Снижение технических рисков и отказов
- Повышение точности прогнозирования потребностей в ЗИП и сервисе
- Повышение качества обоснования коммерческих предложений

---

# 2. Текущая ситуация (как мы её понимаем)

Сейчас анализ технического состояния оборудования осуществляется **вручную** на основе разрозненных источников:

- Паспорта оборудования
- Сервисные отчёты
- История закупок
- Экспертные знания отдельных специалистов

**Ключевые проблемы:**
- Данные неструктурированы и хранятся без единого контекста
- Невозможно системно выявлять скрытые риски
- Невозможно прогнозировать будущие отказы
- Сложно аргументированно обосновывать сервисные и закупочные решения

**Участники процесса:** технические эксперты и коммерческие сотрудники

---

# 3. Предлагаемое решение

## 3.1 Компоненты системы

Согласно вашему описанию, система должна включать:

| # | Компонент | Назначение |
|---|-----------|------------|
| 1 | **Система хранения данных** | Документное и векторное хранилище для долговременной "памяти" |
| 2 | **AI-аналитический модуль** | LLM с RAG-архитектурой для анализа и генерации рекомендаций |
| 3 | **Интерфейс загрузки данных** | Для экспертов/аналитиков — загрузка и работа с данными |
| 4 | **Интерфейс аналитики** | Для коммерческих пользователей — потребление аналитических выводов |

## 3.2 Требования к LLM

Согласно вашим ожиданиям:
- Использование LLM в архитектуре RAG с векторным хранилищем
- Поддержка многоисточниковых данных
- **Нет жёсткой привязки к одному провайдеру**
- Возможность последующего масштабирования

## 3.3 Масштаб первого этапа

- Одно предприятие
- Ограниченное число установок и оборудования
- Формат: **PoC** (Proof of Concept)

├── Логика генерации рекомендаций

ЭТАП 4: ИНТЕРФЕЙСЫ                                          [~2 недели]

## 4.4 Функции PoC

### Для технического эксперта:
- Загрузка документов (паспорта, отчёты, журналы)
- Просмотр оборудования и связанных данных
- Вопросы к AI по оборудованию
- Просмотр прогнозов и рекомендаций

### Для коммерческого сотрудника:
- Дашборд с общей картиной
